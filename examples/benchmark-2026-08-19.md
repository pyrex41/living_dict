# Benchmark run: FizzBuzz and Shen todo app

Date: 2026-08-19

This is an observational run, not a leaderboard result. Each arm used an
isolated temporary workspace. The FizzBuzz task used the repository's existing
hidden claims. The todo task used a Living Dictionary-generated contract that
was automatically approved once and then frozen.

## FizzBuzz

Prompt: `compare/fixtures/fizzbuzz/PROMPT.md`

| arm | result | wall time | turns/tool calls |
|---|---:|---:|---:|
| Grok | claims pass | 138.4 s | 3 turns |
| Pi | claims pass | 21.9 s | 5 tool calls |
| Living Dictionary | claims pass | 9.7 s | 1 episode |

This is one task and one repetition. Grok's latency was a provider outlier;
the result should not be generalized.

## Shen todo app

Prompt:

> Use github pyrex41/bifrost to set up shen-go, then build me a simple todo
> webapp using that for a Shen backend; write the frontend in Shen too using
> pyrex41/ShenScript; use bifrost --shake for performance.

The contract proposal was generated by the Living Dictionary claims pass and
auto-approved. It contained six claims: Bifrost/Shen sources, a `build.sh`
using `bifrost --shake`, a `todo-server` build, and HTTP/frontend checks.
The full approved proposal is retained in the originating run directory as
`claims.approved.json`.

### Contract-authoring run

Living Dictionary approved the proposal and discharged it in two episodes:

- Episode 1 wrote the Shen sources and initial build/server files, but failed
  the build and HTTP checks.
- Episode 2 repaired the build path and discharged all six claims.
- Wall time: 137.1 s.

This demonstrates negotiated-contract recovery, but is not by itself a fair
cross-agent score because the proposal was produced by the Living Dictionary
planner.

### Frozen-contract cross-arm run

The same frozen claims file was supplied to every arm in isolated workspaces.

- Grok: provider call exceeded the practical observation window (~4 minutes)
  and was terminated; no score was recorded.
- Pi: provider call similarly remained active for ~3 minutes and was
  terminated; no score was recorded.
- Living Dictionary: planner completed in 46.0 s and reported its own claims
  discharged, but the external hidden-claims pass failed `build.sh` and HTTP
  checks because those executable checks were not authorized in the compare
  process's context. Cross-arm score: fail.

Therefore this run does **not** establish a winner for the todo task. It
identifies two harness issues to fix before benchmarking: provider timeout
handling and portable authorization/execution of approved check claims.

## Reproduction

FizzBuzz:

```bash
python3 client/compare.py \
  --prompt-file compare/fixtures/fizzbuzz/PROMPT.md \
  --claims compare/fixtures/fizzbuzz/claims.json \
  --arms grok,pi,livingdict --max-turns 8 --timeout 600
```

Todo contract approval:

```bash
bin/livingdict tui --contract --cwd <workspace> --run-dir <run-dir>
```

The approved contract must be frozen before any arm is run. Do not use a
planner-generated contract as evidence of comparative superiority without
also reporting its assumptions.
